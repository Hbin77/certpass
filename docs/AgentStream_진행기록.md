# AgentStream LLM + RAG 진행 기록

목적: 규칙 엔진 판정마다 "왜 이 등급인지" 설명과 근거 인용을 붙인다. 판정 등급은 규칙 엔진이 정본이며 LLM은 등급을 바꾸지 않는다. 화면에 "참고용 설명, 공식 인증 아님"을 표시한다.

- 플랫폼: AgentStream https://agentopen.jntp-ax.or.kr (계정 axhack21, 워크스페이스 "AX 해커톤 7팀" — 사용자 확인 2026-11-07)
- 모델: LLM qwen3.5-122b, 임베딩 bge-m3
- 담당 세션: ax-3b (ax-45에게서 넘겨받음)

## 요약 (발표 세션용, 2026-11-08 00:4x 기준)

| 항목 | 내용 |
|---|---|
| 역할 | 규칙 엔진 판정마다 '왜 이 등급인가·먼저 할 일'과 근거 번호를 붙이는 설명. **등급은 규칙 엔진이 정하고 LLM은 바꾸지 않음**(프롬프트 고정, 화면에 '참고용, 공식 인증 아님') |
| 구성 | AgentStream: 모델 JNTP qwen3.5-122b(LLM)·bge-m3(임베딩) → 지식베이스 `7팀_CertPass_인증요건_v2`(인증 카드 56장을 14개 문서로, 줄마다 카드 꼬리표 [EUCPNP]) → RAG 에이전트 `7팀_CertPass_RAG`(Hybrid 검색 + rerank, 6건) → 공개 챗봇 `7팀_CertPass_판정설명` → API Key. 앱: `certcheck/llm_client.py`, `POST /api/explain`, 판정 행을 펼칠 때 따로 불러옴 |
| 실측 | 검색(카드 56장, 실제 API): 맞는 카드가 상위 5건 안 100%, 1위 정확도 85.7%→96.2%, **상위 5건 중 맞는 카드 조각 70.4%→81.9%→96.5%**(꼬리표로 찾기 → 줄마다 꼬리표). 두 번째 제품 D5에서도 96.7%. 최종 저장본: D3·D5 100건 모두 이 카드 근거 1건 이상(D3 91.2%·D5 96.2%). **뜻 점검(저장본 100건 전부, 729문장): 맞음 90.4%·왜곡 9.3%·지어냄 0.3%→0**(트로메타민 해설 줄로 고친 11건은 80.0%→92.4%). 설명 1건 6~8초, 옛 프롬프트 약 37K 토큰(짧은 프롬프트 수치는 토큰 사용량 화면으로 확인 대기) |
| 안전장치 | 근거에 없는 날짜·비율·용어·인용 '확인 필요', 근거 목록에 없는 '(근거 n)'은 지우고 표시, 플랫폼 안내문은 설명으로 쓰지 않음, 이 카드 조각만 출처로 표시, 실패해도 판정·근거 그대로, 분당·시간당·방문자별·하루 상한, 리다이렉트 거부(Key 재전송 방지), Key는 서버 .env.agentstream(600)에만 |
| 저장된 설명(바로 뜸) | D3·D5 전부(각각 해당 없음은 설명 생략). D1·D2·D4는 펼칠 때 생성(6~8초). 점검(토큰 0) 100건: 이상 없음 95, 나머지는 '확인 필요'로 화면 표시 |
| 한계 | 화면의 자동 점검은 용어·숫자·인용·근거 번호 대조라 뜻이 틀린 문장은 못 잡음('확인 필요' 표시만) — 뜻은 검토 에이전트로 따로 잼(남은 왜곡 약 9%, 주로 조건·작성 주체). 질문 1건 토큰: 옛 프롬프트 약 37K, 짧은 프롬프트는 실측 미확인(토큰 사용량 화면으로 확인 대기). 7팀 LLM 일간 토큰 한도 12M — 넘으면 새 설명은 '모델 사용 한도' 안내, 서버 하루 새 설명 상한 200 |
| 만들며 겪은 문제 | ① 프롬프트 줄 머리 `[1]`을 AgentStream이 JSON 표로 읽어 실패 → '근거 1:' 형식 ② 지식베이스 변환이 밑줄을 지워(EU_CPNP→EUCPNP) 키워드 검색이 빗나감 → 꼬리표 모양 맞춤 ③ 일정 길이로 잘린 조각에 카드 표시가 없어 다른 카드가 섞임 → 줄마다 꼬리표 ④ 285KB 파일은 처리 실패 → 38KB 이하로 분할 ⑤ 측정·미리 만들기로 일간 토큰 한도 소진(LLM_RATE_LIMITED가 '순간 한도'로 표시) → 해당 없음 생략·하루 상한·토큰 아껴 쓰기 |

## API 형식 (AgentStream 사용 가이드 /docs 'Codex용 연동 가이드' 본문, 2026-11-07 19:3x 확인)

| 단계 | 요청 | 응답 |
|---|---|---|
| 상태 | GET {BASE}/open/v1/chatbots/{chatbot_id}/health | 200, status(healthy/unhealthy/unknown)·message·checked_at |
| 세션 | POST {BASE}/open/v1/chatbots/{chatbot_id}/sessions, 본문 {"query": 첫 질문} | 201, 최상위 session_id (세션 생성만으로 답변은 안 나옴) |
| 질문 | POST {BASE}/open/v1/chat-sessions/{session_id}/messages, 본문 {"message": 질문} | 200 application/x-ndjson. assistant.delta의 content(배열이면 text 블록만), assistant.replace, turn.completed=정상 종료, turn.failed(category TOKEN_LIMIT/LLM/RAG/SERVER), references[type=rag]=문서 출처 |

- 인증: 헤더 X-API-Key. BASE = https://api-gateway.jntp-ax.or.kr/agentstream (화면 표시값). 일반 /api/* 는 Key로 못 씀.
- 오류: 401 Key, 403 챗봇 비공개·다른 조직·CHAT_INVOKE 권한 없음, 404 ID, 503 동시 처리 한도. 실패한 POST는 자동 재전송하지 않는다.
- 지식베이스 파일 형식: .md .txt .pdf .docx .hwp .hwpx .csv (화면 코드에서 확인)
